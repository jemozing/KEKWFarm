# KEKWFarm

KEKWFarm — ферма для Attack & Defense CTF на Go. Центральная панель принимает флаги, хранит очередь и результаты в SQLite и отправляет флаги чекеру соревнования. Раннер запускает скрипты по расписанию на своей машине и отправляет найденные флаги в панель.

У панели и раннера отдельные веб-интерфейсы. Панель можно запустить самостоятельно, а к одной панели можно подключить несколько раннеров. Для Go-версии достаточно SQLite на стороне панели.

## Быстрый старт

Для панели понадобятся Docker с поддержкой Linux-контейнеров и Docker Compose v2. Go на хосте нужен только для нативной сборки и тестов. При первой сборке Docker скачивает базовые образы и Go-модули.

В корне скачанного репозитория создайте локальную конфигурацию.

```sh
umask 077
cp -i duckfarm.example.json duckfarm.json
mkdir -p vol/duckfarm-go/data
```

Создайте в корне файл `.env` с собственным паролем вместо примера.

```dotenv
SERVER_PASSWORD='replace-with-your-own-password'
```

```sh
KEKWFARM_USER="$(id -u):$(id -g)" docker compose up --build -d farm
```

`KEKWFARM_USER` задаёт UID и GID процесса в контейнере, чтобы панель могла читать локальный конфиг и писать в SQLite. Если записать в `.env` числовую пару, которую выдают `id -u` и `id -g` (например, `KEKWFARM_USER=1000:1000`), для обычного запуска достаточно `docker compose up -d farm`. После изменения исходников добавьте `--build`.

Для запуска Runner WebUI вместе с панелью выполните `make start-runner`. Эта команда подготавливает каталоги раннера и определяет группу сокета Docker.

| Интерфейс | Адрес | Что доступно |
| --- | --- | --- |
| Центральная панель | [http://127.0.0.1:5137](http://127.0.0.1:5137) | Флаги, команды, статистика, чекер и регистрация раннеров |
| Runner WebUI | [http://127.0.0.1:5138](http://127.0.0.1:5138) | Подключение к панели, расписание, загрузка скриптов и логи |

По умолчанию обе панели используют пароль из `SERVER_PASSWORD`. Для отдельного пароля Runner WebUI задайте `KEKWFARM_RUNNER_WEB_PASSWORD` в `.env`.

## Подключение раннера

1. В центральной панели откройте **Runners**, введите имя раннера и нажмите **Register**. Скопируйте токен, пока он отображается.
2. В Runner WebUI откройте **Connection**. Для двух сервисов в одном Compose оставьте адрес `http://farm:5137`. Для отдельной машины укажите адрес центральной панели, доступный с раннера.
3. Вставьте токен и нажмите **Save connection**. После успешного heartbeat статус **Online** появится в верхней панели Runner WebUI и на странице **Runners** центральной панели. Там же видны адрес раннера, время последней связи и счётчики заданий.

Токен выдаётся одному раннеру и используется для получения конфигурации, отправки флагов и heartbeat. Для входа в веб-интерфейс используется пароль. Если токен нужно заменить, зарегистрируйте новый раннер, сохраните новый токен в **Connection** и отзовите старый через **Revoke**. Сохранённые настройки подключения имеют приоритет при перезапуске.

## Настройка игры

- В `duckfarm.json` задайте `teams` как объект «имя команды → адрес». Адрес команды передаётся скрипту первым аргументом.
- В центральной панели откройте **Checker**, выберите пресет соревнования и заполните его поля. Для ручной настройки используйте **Edit JSON**. Сохранённые настройки применяются к новым пакетам отправки и хранятся в SQLite. Они имеют приоритет над блоком `checker` в `duckfarm.json`.
- В **Checker → Flag format and timing** можно настроить регулярное выражение флага, срок хранения в очереди с момента приёма, интервал отправки и размер пакета. **Save flag settings** сохраняет их в SQLite отдельно от настроек чекера. При первом запуске используются значения из `duckfarm.json`. После сохранения настройки из панели имеют приоритет и применяются без перезапуска. Раннеры получают новый формат при следующей загрузке конфигурации игры.
- Для пробного запуска оставьте **Disabled** в разделе **Checker**. Панель будет принимать флаги и складывать их в очередь. Адрес чекера при включённой отправке должен быть доступен из контейнера панели.

Чтобы применить изменения файла конфигурации к панели, пересоздайте её контейнер с UID и GID пользователя, которому принадлежат локальные файлы.

```sh
KEKWFARM_USER="$(id -u):$(id -g)" docker compose up -d --force-recreate farm
```

### OmCTF и Skipper

1. В **Checker → Flag format and timing** нажмите **Fill OmCTF defaults**. Панель заполнит формат `[A-Z0-9]{31}=`, срок жизни в очереди **600 секунд** и предложит интервал отправки **2 секунды**. Проверьте **Flags per batch** и нажмите **Save flag settings**.
2. В **Checker** выберите **OmCTF · Skipper (forcad_http)**. Адрес `http://10.10.10.10/api/v1/flags` заполнится автоматически. Убедитесь, что этот адрес доступен из контейнера панели через VPN соревнования. Вставьте командный токен из `skipper-token.txt` в **Team token** и нажмите **Save checker**.
3. В Runner WebUI задайте **Interval (seconds)** равным `120`, если задание должно запускаться раз в раунд.

## Первый запуск скрипта

Сохраните пример в `probe.py` на компьютере, с которого открываете Runner WebUI. Скрипт печатает синтетический флаг и не обращается к адресам команд. Для него подходит `flag_format` из примера конфигурации.

```python
print("A" * 31 + "=", flush=True)
```

1. В Runner WebUI откройте **Jobs**, загрузите `probe.py` в поле **Exploit file** и выберите **Python 3**. Для первого запуска оставьте поля Dockerfile и Docker image пустыми.
2. Оставьте **Start time** пустым для старта сразу или укажите время в часовом поясе браузера. В **Interval (seconds)** задайте `0` для одного запуска, `60` для запуска раз в минуту или свой интервал. Если Docker ещё скачивает образ, на первый запуск поставьте таймаут, например, `120` секунд.
3. Нажмите **Schedule job**. Откройте **Logs** у задания и проверьте вывод. В центральной панели откройте **Flags**. При выключенном чекере новый флаг появится со статусом `QUEUED` и останется в очереди до истечения срока действия.

За один раунд раннер проходит по адресам из `teams`. **Parallelism** ограничивает число одновременно запущенных контейнеров. Поле **Timeout per target** задаёт лимит для отдельной цели и дедлайн раунда, включая подготовку образа и отправку флагов. Раунды одного задания идут последовательно. Если раунд ещё работает к началу следующего, очередной запуск пропускается.

### Зависимости через Dockerfile

Раннер принимает один Python-файл, shell-скрипт или исполняемый файл для Linux размером до 10 МиБ. Можно указать готовый **Docker image** или приложить **Dockerfile** размером до 256 КиБ. Без обоих используется `python:3.14-slim-trixie`.

Пример Dockerfile для скрипта, который импортирует `requests`.

```dockerfile
FROM python:3.14-slim-trixie
RUN pip install --no-cache-dir requests
```

В контекст сборки попадают Dockerfile и загруженный скрипт под исходным именем. Первый раунд собирает образ, следующие переиспользуют его. Для каждой цели раннер запускает отдельный контейнер с выбранным интерпретатором и ищет флаги в stdout и stderr. Используйте скрипты, Dockerfile и образы из доверенных источников.

## Доступ по сети

### Панель и раннер на одном хосте

По умолчанию порты доступны только через `127.0.0.1`. Чтобы открыть их в локальной сети, добавьте в `.env` строки ниже и замените IP на LAN IPv4-адрес Docker-хоста.

```dotenv
COMPOSE_FILE=compose.yml:compose.lan.yml
KEKWFARM_LAN_IP=192.168.31.20
```

Повторите `make start-runner`. В этом примере панель доступна по `http://192.168.31.20:5137`, а Runner WebUI — по `http://192.168.31.20:5138`. Если адрес фермы уже сохранён в **Connection**, при необходимости обновите его там. LAN-конфигурация передаёт адрес хоста в heartbeat. Без заданного адреса панель показывает исходный IP подключения, который в Docker может принадлежать контейнеру или шлюзу.

### Раннер на отдельной машине

Скачайте проект на машину раннера. В её локальном `.env` укажите адрес центральной панели и пароль для входа в Runner WebUI. Пример ниже использует адрес панели в локальной сети. За пределами доверенной сети используйте HTTPS-адрес панели.

```dotenv
KEKWFARM_FARM_URL=http://192.168.31.20:5137
KEKWFARM_RUNNER_WEB_PASSWORD='replace-with-a-runner-password'
KEKWFARM_RUNNER_CONFIG_FILE=./duckfarm.example.json
```

Запустите только сервисы раннера из базового Compose. Пример рассчитан на Linux с сокетом Docker в `/var/run/docker.sock`. Для другого пути задайте `KEKWFARM_DOCKER_SOCKET` и получите GID группы этого сокета.

```sh
umask 077
mkdir -p vol/duckfarm-go/runner/uploads
KEKWFARM_USER="$(id -u):$(id -g)" \
KEKWFARM_DOCKER_GID="$(stat -L -c '%g' /var/run/docker.sock)" \
docker compose -f compose.yml --profile runner up --build --no-deps -d runner-engine runner
```

На машине раннера откройте `http://127.0.0.1:5138` и добавьте токен в **Connection**. Для просмотра интерфейса с другой машины можно пробросить этот порт через SSH.

## Обслуживание и CLI

```sh
docker compose --profile runner ps
docker compose --profile runner logs -f farm runner runner-engine
docker compose --profile runner down
```

Панель хранит базу и настройки чекера в `vol/duckfarm-go/data`. В `vol/duckfarm-go/runner` хранятся задания, настройки подключения, загруженные файлы и логи. Эти каталоги сохраняются после `down`.

Для нативной сборки и тестов используйте Go 1.26 или новее.

```sh
make test
make build-native
```

Консольный раннер принимает токен из файла. Сохраните выданный токен в локальном файле с правами `0600`. Пример ниже предполагает, что `probe.py` и этот файл уже существуют.

```sh
./bin/duckrunner --server-url http://127.0.0.1:5137 \
  --token-file ./runner.token --interpreter python3 ./probe.py
```

Для перехода с Python-версии перенесите команды, формат флагов, интервалы и настройки чекера из `server/app/config.py`. История флагов требует отдельного переноса из PostgreSQL в SQLite. Для совместимости сохранён старый стек с PostgreSQL, Redis и отдельным фронтендом. В нём токены чекера задаются через `TEAM_TOKEN` или `SYSTEM_TOKEN` в зависимости от протокола. [Compose для Python-версии](compose.legacy.yml)
